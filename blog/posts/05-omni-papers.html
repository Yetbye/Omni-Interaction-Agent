CHAPTER 01

ALIVE：把「沉默」建成显式动作 2026-11-21 · 全文精读修订

流式视频模型可以一直看着世界，却往往把用户请求当成孤立事件处理。ALIVE（arXiv 2611.21366）给出的答案是：交互性必须由动作词汇表来承载——何时响应、如何响应、何时沉默，外加主动追问（feedback-seeking）。

全文级本章已由摘要级升级为全文级：论文全文 PDF 已获取并按 16 页文本提取读毕（存档 docs/sources/papers/2611.21366-alive.txt，精读笔记 docs/sources/papers/notes/05-alive.md），本章数字与方法细节以论文全文为准；官方代码仓 github.com/lijinzhao30/ALIVE 与项目页 lijinzhao30.github.io/ALIVE（此处仅纯文本记录，全站离线不设外链）。

为什么「沉默」要被写成一个动作

在多数 agent 设计里，「不回复」是缺席（absence）：没有事件、没有日志、也就没有可优化的对象。ALIVE 把它翻转成一个可被训练、可被打分的显式动作。全文的形式化（正文 §3.1）给交互式流式模型的输出是三类语义：

  • 输出词汇表（Eq. 2）：o_τ ∈ { r_τ（回应或保持沉默）, c_τ（请求澄清或反馈）, a_τ（请求用户执行动作）}——c 与 a 合起来就是「寻求反馈」的两种形态：要信息 vs 要动作。诚实标注：本页一直沿用的「三态决策」是摘要级的简化命名，论文原文的实际控制粒度是二元控制 token（R 回应 / S 沉默）+ 策略文本，r/c/a 是三类输出语义而非三个控制态。
  • 能力分类学（正文 §3.2）：三族共 8 个任务类型——Proactive Monitoring（首次条件满足即通知 / 触发与答案证据齐备才回答 / 跨多次出现各回应一次）、Streaming Task Coordination（任务状态更新 / 并行请求保留其余承诺）、Feedback-Seeking Interaction（Ask-for-Monitor / Ask-for-Information / Ask-for-Execution）。
  • 两阶段训练：ALIVE-SFT-288K 精确为 288,436 条、ALIVE-RL-3K 精确为 3,523 条（摘要取整），另混入 274K / 800 条精选 reactive QA 保住通用问答；对比式 SFT 教「何时与如何响应」，RL + BACA 负责精修决策、响应与沉默。
  • FSI-Bench（正文 §5.2）：1,235 个 episodes、4 个任务（Ask-for-Monitor 154 / Ask-for-Information 446 / Ask-for-Execution 459 / Direct Answer 176），双协议 EDP（显式决策）与 FDP（自由形式由 LLM judge 推断）；计分 D = d，T = d·1[t_r ∈ W]，A = T·a——追问不是目的，追问后在有效窗口内把事办完才算数。
  • 自报在四个公开基准与 FSI-Bench 上取得被比较模型中的最高总分自报·未复现（真实数字见下文主结果）。

方法细节：两阶段各解决哪类失败

  • 对比式 SFT 的两族受控对比（正文 §4.1）：Response-gate contrasts 固定视觉前缀只变交互条件（同一目标出现，活跃监控下要通知、取消后要沉默）→ 监督「该不该说」；Action-strategy contrasts 固定任务只变证据可得性/指代歧义（证据充分→直接回答、歧义→澄清、缺证据→请求用户动作）→ 监督「说什么策略」。训练实例以标注回应为中心采样偏移 δ∈{0..4}、视觉窗长度 N~U[10,30]（1 FPS），窗内只监督最后一条回应与全部沉默 token，沉默按 nR/nS 加权。
  • BACA（正文 §4.2）：奖励 R_i = D_i · C_i · P_i（策略正确性 × 任务完成度 × 冗余惩罚 exp(−λ·K_i/max(1, N_i^req))）；把轨迹按标注构造行为单元——覆盖策略选择、任务回应、关键沉默三方面；轨迹级优势组内归一化 A^E、单元内局部优势 A^B，调用级合并 A = A^E + α·A^B（α=1），不在任何单元内的调用只拿轨迹级优势；目标函数为组内归一化策略梯度 + 指向冻结 SFT 模型的 KL 正则。「关键沉默」有专门的信用分配：事件前等待的沉默，只有后续目标也拿到正的完成信用时才获局部信用。
  • 数据管线（正文 §3.3）：24 个公开视频数据集，三步流水线——时序证据锚定与细化（找「视觉条件首次满足」的最早采样时刻）→ 对话合成与时序对齐 → 质量校验（含因果可回答性：答案只能依赖时间戳之前的观察，偷看未来帧即过滤）。
洞察

主动性 = 动作词汇表，而不是音量

ALIVE 最值钱的不是它的分数，而是它把交互拆成了有限且互斥的动作集：响应、沉默、追问。有限动作集带来三个工程后果——动作可枚举（策略有界）、动作可打分（每个状态都有学习信号）、动作可回放审计（事后能归因到「为什么当时没说话」）。

依据：全文 PDF 提取 docs/sources/papers/2611.21366-alive.txt（16 页读毕）+ 笔记 notes/05-alive.md；转译讨论见 report.html §5.2。

为什么采用「对比式 SFT + RL」两段式

对比式 SFT 的作用是划边界：在同一批情境里给出「该说 vs 不该说」的配对示范，让模型先学会何时与如何响应；RL（BACA）的作用是调长程代价：单轮看似正确的行为在多轮轨迹里可能是打扰，轨迹级优势正是用来惩罚这种「当下正确、全局错误」的选择。这两段各自解决一类失败，替换任何一段都会留下盲区。

批判与转译

哪些迁不走，哪些必须迁

不可迁移：ALIVE 的载体是流式视频模型，其数据集（288,436 + 3,523 条）、两阶段训练法与评测分数，对一个运行在 DSH 上的 harness 层策略器毫无直接用处——report.html §5.2 也记录了「其训练法确不可迁移」的判断。作者自陈的局限同样指向这一点：ALIVE 仍是视觉-语言模型，语音交互需外挂 ASR/TTS，原生 omni-modal 模型是后续方向（正文 §6）——这恰是 OIA 可补的生态位。

可直接迁移：① 动作词汇表 {respond, silent, seek-feedback}（对应全文 Eq. 2 的 r/c/a 语义 + R/S 控制 token）；② 「沉默是显式动作而非缺席」这一原则——BACA 给「关键沉默」单独做信用分配就是明证；③ 追问后必须回到观察的回边结构（追问不是终态）；④ 评估思路：把「追问之后有没有把事办完」单独做成指标（FSI-Bench 的 D/T/A 三级计分）；⑤ 对比式 SFT 的构造法：同一视觉、不同交互条件 → 不同行为的成对样本，是低成本的行为门控监督来源。这五点直接进入 OIA 干预策略器的输出定义，并与本系列第 6 篇的 InterventionPolicy 对接。

取证边界：本章数字来自 PyMuPDF 文本提取（16 页 / 59,401 字符），表格按单元格线性展开后重建、逐格复核未做；图 1/2/3 的图像内容未看。官方仓 github.com/lijinzhao30/ALIVE 仅确认公开可访问，内部代码与权重未逐一核验。

洞察

替代方案：不用 RL 也能有三态吗？

可以。规则式替代（静默时段硬编码 + 被忽略 N 次降频）能拿到三态里的 80%，代价是时机个性化退化为全局阈值——它无法学会「对 A 用户周五下午可以多说一句，对 B 用户永远别在开会时出声」。Coco 正是为补这个短板而生，见下一章。

CHAPTER 02

Coco：观察—保留—适应的闭环 2026-11-21 · 全文精读修订

Deep Personalization / Coco（arXiv 2611.13457）要解决的是一个尴尬缺口：用户仍得自己判断「什么时候该找 AI 帮忙」，于是大量本可被帮忙的时刻被错过。主动智能体承诺补上这个缺口，但有效的主动性要求理解用户实时活动、并把干预时机个性化——帮在合意的时刻，而不是打扰的时刻。

全文级本章已由摘要级升级为全文级：arXiv HTML 全文（2,376 行，含附录 A–F）与两个官方仓（NVlabs/deep-personalization 主仓 + collaborative-agents/coco 集成仓，Apache-2.0）均已读毕，代码实测见章末——数字以论文全文/代码为准（笔记 docs/sources/papers/notes/01-deep-personalization.md）。

闭环的四段：观察 → 选择性保留 → 干预决策 → 隐式反馈

  • 持续观察：独立的 Observer Agent（正文 §3.1，式 2/3）单次 prompt 输出结构化四字段 o_t = {observation, user_intent, rationale, need_support}——它同时是「记忆写入格式」与「决策格式」；y_t=1 时唤起下游 Execution Agent，y_t=0 继续被动观察。
  • 选择性保留：长期记忆是命题-观察二部图（正文 §3.2）——Observer 输出与高层用户命题两端，命题由同一个模型按 GUM 定期合成，新命题检索 top-k 最相似既有命题判「新建 vs 修订」；上下文 = k 条最近输出 + k 条最相关命题。诚实标注：k 的取值未在全文给出（benchmark 代码里 RECENT_OBSERVATION_LIMIT=5）。
  • 干预决策与四类隐式信号：投入（engagement）、忽略（dismissal）、显式请求（explicit requests）、重复工作模式（repeated work patterns）。
  • 适应：两条低资源路线——Coco-PE（ACE 式 Generate-Reflect-Curate 的 bullet-point 指令记忆，用户可读可审）与 Coco-LoRA（rank 32 / α 64 / 1 epoch）；正文自报 Qwen 系上 PE 更强、Nemotron 上 LoRA 更强。
  • 隐私 rationale：change-aware 选帧 + observation-first 调度让 Observer 跑在本地，不把原始活动流外发——但全文的诚实版本见下文批判框（Execution Agent 走云端）。

摘要没有的机制：回溯扫描与标签合成

摘要只列四类信号；正文 §3.3 还有一整套回溯扫描，其动机是论文明确论证的反退化设计：若只用「干预后用户参与 / 拒绝」两个信号，Observer 会学到「少干预 → 更少信号」的退化策略——越沉默越安全，越安全越沉默。补救是用同一个 on-device 模型回溯扫描整条时间线：

  • 三类机会：repetitive_work | stuck | anticipate_need（代码 retrospective.py:RETROSPECTIVE_CATEGORIES 与附录 B.3 完全对应）；硬规则包括「机会必须在后继行为之前就可推断」「事后手动打开 ChatGPT 是正面证据」「不得仅凭沉默推断偏好」、证据至少 3 个互不相同的 observation id。
  • 三段式 prompt：发现机会 → 落到最早可推断的触发点（置信度 ≥0.75 门槛）→ 极性被推翻后改写观察（禁止在输出中提及 label/feedback）。
  • 「沉默后主动求助」= FN 代理：代码 missed_opportunities.py 的 60s 窗口（MISSED_OPPORTUNITY_WINDOW_S=60）——决策为 no 但 60 秒内出现用户求助，即给该决策打负反馈（missed intervention opportunity）。论文自陈这是「潜在支持机会」而非「已确认偏好」。
  • 标签合成（labeling.py:label_moment()）：多源信号加权投票 score = Σ signed_score()，|score| < 0.45 直接丢弃不打标签；>0 记 yes、<0 记 no，confidence = |score|/Σ|conf×weight|；信号策略表（FEEDBACK_POLICIES）带 30 分钟 TTL；未经纠正的 no-support 预测按 confidence 0.25 作弱负例。

洞察

没有标签就没有学习信号

「什么时候该说话」直觉上是个品味问题，无法梯度下降。Coco 的关键一步是把品味变标签：通过数据合成管线，把已有 computer-use 轨迹改造成带「人格化干预标签」的基准——于是「干预时机」第一次成为能算 macro F1 的监督任务。闭环里其余所有环节（观察、保留、适应）都以这个标签为前提：可度量化是闭环成立的入场券，不是加分项。而在线侧的 |score| < 0.45 不打标签 是同一枚硬币的反面：没有可信标签时宁可留白，也不喂噪声。

依据：全文笔记 notes/01-deep-personalization.md §4.1–4.6（Table 1/2、§6.2）；report.html §6.1。

为什么必须是独立的 Observer，而不是塞进主对话

代价与替代方案：把观察塞进主 agent 上下文的替代方案更省架构，但会付出三重代价——上下文被桌面噪声污染、观察与回答互相争抢注意力、原始活动随对话日志扩散。独立 Observer Agent 把三件事一起解决：观察上下文紧凑且专用、不占主对话窗口、隐私边界可以物理地画在 Observer 与网络之间。这也正是 report.html §5.2 的转译结论：观察者独立成 subagent（不占主对话上下文）。正文 §4 还给出配套的工程三件套：change-aware 选帧（MSE τ=8000，DGX Spark 上 KV 命中 26.7%→45.2%）、observation-first 调度（空闲 60s 才做轻量修订、600s 才全量演化、前台永远抢占）、DFlash 投影解码（draft block=8）自报·未复现。

批判

闭环的四个诚实缺口（全文级才看得到）

① 隐私自陈比摘要保守：摘要说「不外发原始活动流」，附录 A 却明说 Execution Agent 目前依赖云端大模型，检索出的用户上下文可能离开设备——原话是「reduces but does not eliminate privacy risks」；README 更直白：屏幕理解会把截图发给你选择的模型提供方，用本地模型才能全程留在本机。转译到 OIA：应在 Governance 显式建模「哪些记忆块允许注入云端推理请求」，而不是笼统宣称本地隐私。

② 数字口径疑点：引言写「reaches up to 0.77 F1 on one of the personas」，但 Table 1 单 persona 最高为 0.8609（Nemotron / Coco-LoRA / Eager Hands-on），全文未找到 0.77 对应的单元格（可能笔误或另一聚合口径）。用户研究的 0.199→0.515 是 F1 proxy（三类事件代理），非人工标注真值，且脚注承认 FN 被低估。

③ 仓库与论文三处不一致：persona 池代码 5 个（多一个 minimal_interruptions）vs 论文 4 个；--test-ratio 默认 0.2 vs 附录 C 的 70/30；Observer prompt 三个版本并存（论文 B.1 / benchmark 69 行 / 部署版 10 字段输出）。复现须以论文附录 + 发布数据集为准。

④ 反馈稀疏与缺席证据：「忽略 dismissal」既可能是「打扰到了」也可能是「在忙」；60s 求助窗口与回溯扫描正是为补这个洞，但它们都只是「机会证据」而非确认偏好——这恰是 report.html §5.3「被忽略 N 次 → 降频 + 记负反馈」要处理的粒度。

CHAPTER 03

Pandora：内容与说话方式的分离 2026-11-21 · 全文精读修订

前两章解决「何时出声」，Pandora（arXiv 2611.00617，Words Caught in the Heart）解决「怎么说」。它的场景是心理咨询来访者模拟，而它对 OIA 的启示远超心理场景：决策与语言实现必须分层。

全文级本章已由摘要级升级为全文级：arXiv HTML 全文（约 370KB，含附录 A–I）读毕（笔记 docs/sources/papers/notes/02-pandora.md）。重要更正：官方代码为悬空声明——Appendix A.1 / I.3 / I.4 三处声称「the repository listed on the first page」，但全文 100+ 条外链逐一核对后无一指向 Pandora 自身代码，abs 页亦无 Comments/Code 链接；按「未在全文中找到官方代码」记录，本页据此不提供任何代码链接。

四段流水线：状态 → 归因 → 内容 → 表达

  • 状态更新（§3.1 + Appendix A.2/A.3）：纯规则、不需要单独的 LLM（原文明示）。状态是 12 个数值维度（distress / defensiveness / trust / perceived safety / disclosure readiness / insight …），干预类型缩放系数从 practical exchanges 0.10 到 invalidation 1.00；trust 与 perceived safety 额外用惯性加权：旧值 0.75 + 提议有界值 0.25，再加 field-specific 步长限制与值域约束——有界 + 惯性，避免状态跳变驱动过激输出。
  • 主观归因与披露规划（§3.2）：构建主观评价（appraisals）与归因，且归因是一条光谱（具体情境 → 试探性关系解释 → 底层信念），干预信号调节「解释被表述得多清楚」——同一份案例材料随交互支撑不同的主观叙述，即使来访者开始看清问题也保留不确定性。
  • 内容与策略（§3.3）：C_t = (a_t, b_t, d_t, r_t)；stance（hesitant / defensive / confused / emotionally overwhelmed / open）与 purpose（answer-first / brevity / confirm-or-refine / resist-or-clarify）分离——允许「犹豫但直接作答」这类组合。
  • 独立表达规划器（§3.4，式 2）：L_t = F_realize(s_t, C_t, H_{t-1}, ρ)——ρ 是离线蒸馏、跨轮复用的个体语言 profile（习惯性话语标记、hedging、情感显式度、句长分布、句数五件套）；在线逐轮指定 6 类槽位（speech style / pronoun focus / certainty / emotional explicitness / hedging / length 与句数目标）。分工纪律一句话：「Explicit rules organize the intermediate plans, and the LLM supplies their linguistic realization」——规则组织中间计划，LLM 只负责兑现成自然语言，且明令数值状态字段与内部 id 不得写进话语。
  • 评测：115 个案例（97 中文 + 18 英文；实为 97 PsyDial-D4 + 11 AnnoMI + 5 Eeyore + 2 ConsistentMI，构造漏斗 5,754→2,084→509→115）与五个基线比较；自报取得最高 expression similarity 与 overall disclosure-alignment自报·未复现。
  • 四评人研究：对 45 个配对披露条目（L1–L3 每层 15 个），Pandora 被判「像 AI」的评分为 7.2%（13/180），而基线为 43.3–67.2%、去掉表达规划后为 35.6%自报·未复现。
洞察

「self-opaque」：不该说得比本人还清楚

Pandora 的原始动机指出：来访者在能连贯描述之前就已感到痛苦，而基于临床案例描述的模拟器容易给出「比当事人当前理解更清楚」的解释——这被称为过度自我阐释的风险。诚实记录：「self-opaque」术语本身只出现在标题，正文 grep 零次定义，其操作化落点在 Appendix G 的 AI 味判定 rubric：负面线索 = 模板化总结、excessive completeness（把话说满）、泛泛的心理解释、亲密披露与权威解释声不匹配——「过度完整的自我解释」被直接等同于需要抑制的 AI-like 症状。翻译成 OIA 的语言：对用户自身状态的推断要克制、留白；系统可以组织信息，但不能替用户宣称「你其实是想……」。

依据：全文笔记 notes/02-pandora.md §3.5、§5.1；report.html §6.1 对应条目。

为什么要把表达规划器做成「独立」组件

为什么：如果风格与内容在同一个生成步骤里决定，风格就无法被单独评测、单独替换、单独做克制检查；消融实验也证明了这一拆分的必要性——去掉表达规划后「AI 味」评分从 7.2% 升到 35.6%自报·未复现，说明贡献确实来自这一层，而不是来自更大的模型。代价：多一层就多一次推理调用与一次上下文拼接。替代方案：用系统提示词统一注入风格（更便宜），但只能得到全局风格，得不到「从该用户话语蒸馏」的个人风格。

CHAPTER 04

Omni-IO：能力扩展发生在 harness 层 2026-11-21 · 全文精读修订

Omni-IO Skills（arXiv 2609.31847）的出发点是一个成本曲线问题：通用智能体会规划、推理、长程行动，但生产能力仍碎片化在文本、图像、音频、视频、文档、3D 资产与代码之间。把基础模型扩展到新模态，等于把能力增长绑定到昂贵的模型更新上；而拼装专家模型与工具，又留下过程、依赖、中间资产与跨轮修订如何协调的未解问题。

全文级本章已由摘要级升级为全文级：arXiv HTML 全文（331KB，正文 7 节 + 2 附录）与开源仓库镜像 docs/sources/repos/omni-io-skill/ 读毕（笔记 docs/sources/papers/notes/03-omni-io.md）；官方仓 github.com/any2any-mllm/Omni-IO-Skill（纯文本记录，全站离线不设外链；仓库内未找到 LICENSE 文件）。

四个组件与一张执行图

  • 分层 Skills（§4.2）：三级按任务粒度而非模态划分——Atomic（19 个，最小可独立调用单元）/ Expert（2 个，面向单一最终交付物的完整生产流程）/ Scenario（6 个，一组关联交付物，19+2+6=27，可在仓库逐一点数核对）。声明式表示 s = ⟨c_s, I_s, P_s, O_s, H_s⟩（式 1）：输入/输出按语义描述、不绑定 provider，宿主无需加载底层实现即可检查与组合技能；高层技能递归展开直到步骤可执行。
  • 标准化多模态执行接口（§4.3/4.4）：上行 = task type + 自包含 prompt + 依赖已解析的资产输入；下行 = output type + 本地路径 + description + effective parameters，再转交注册表；每个 task type 绑定 tool/provider/model/credential/默认参数/fallback——换 provider 不改 Skill 描述与图结构。依赖专业模型的走 MCP，code/markdown 由宿主原生执行，两条路线遵守同一依赖语义。
  • 持久 Asset Registry（式 2）：八字段 a = ⟨asset_id, type, subtype, path, description, params, turn_id, source_asset_id⟩——asset_id 全局唯一且与物理路径解耦，source_asset_id 记修订血缘；append-only JSON、不原地更新、原子写 + 文件锁、只在写盘成功后才注册。
  • Declare Execution Graph（§5.2/5.3）：G=(V,E)，节点（式 3）v = ⟨id, type, prompt, params, depends_on⟩；一条边同时是控制依赖与数据依赖；历史资产用 asset_source 节点——引用解析后即视为完成、不发任何生成调用。
  • 规模自报：27 个 Skills 覆盖 38 个代表性任务，横跨 7 种工件模态与 4 个能力族（理解 / 生成 / 推理 / 检索）自报·未复现。
  • UniM-90 自报（Table 3）：把 GPT-5.6 Sol 与 Claude Sonnet 5 的输入支持率 τ 从 40.00% 与 38.89% 提到 100%；相对 SQCS 从 26.99 → 74.94（+47.95）、27.82 → 77.78（+49.96）；Strict Structure Score 达到 100.00 与 99.78；τ=100% 时 abs 与 rel 两列相等自报·未复现。
洞察

为什么「不改宿主推理核心」是关键主张

因为它是成本曲线的拐点：改模型的代价随模态数近似线性叠加且每次全量支付；改 harness 的代价是一次性搭建接口与注册表，之后每加一个 Skill 只是目录里多一行。更关键的是可逆性——harness 层的组件可以单独停用、替换后端、按场景裁剪，而一次错误的模型更新是不可分发的回滚。Omni-IO 自报把两家前沿模型的输入支持率拉到 100%自报·未复现，正是用「同一宿主、只换 harness」的设置来证明这一点。

依据：全文笔记 notes/03-omni-io.md §3–§4（Table 3）；对位表见 report.html §7。

DEG 的完整语义：验证、Wave 与失败处理（摘要完全没提的部分）

  • 图验证两条检查（§5.3）：① 每个依赖引用都能解析到某节点或已注册资产；② 诱导子图无环。任一失败视为规划错误、整图重建而非带病提交。
  • Wave 调度四规则：pending 且所有前驱已完成的节点构成下一个 Wave → 同 Wave 内节点互相独立、并发派发 → 无未解析前驱的进最早 Wave、其余进「所有直接前驱已完成」的第一个更晚 Wave → 调度由声明的依赖决定、与模态无关（互不消费的图像与音频可并发，图像条件化的视频必须等参考图）。Table 2 的四 Wave 案例（产品推广）：分析参考图 →（海报素材 ∥ 视频与音效）→ 宣传视频与海报 → 落地页。
  • 失败语义（§5.3 p3）：节点失败 → 其 pending 后代被取消（输入不可得）、独立分支继续执行、记录每个节点终态、不回滚已完成节点的输出。
  • 跨轮复用：历史资产用 asset_ref 指代，其记录被物化为新 DEG 中已完成的源节点、立即对后代可用；修订创建新记录并保留 source 引用、绝不原地更新——「换落地页风格」时只有落地页任务重跑。
  • 注入而非口述：上游完成后按关系注入具名参数（image→video 注入 first_frame_url、image→3D 注入 reference_image_url），下游 prompt 不需要写路径；保守声明原则——缺依赖 = 下游读到空/旧资产 = 高成本错误，多余依赖只损失并行度 = 低成本，宁多勿漏。

代码三层的工程约束（仓库 orchestration/*.md）

  • 单向层级：Skill Index 写死 Scenario → Expert → Atomic 调用方向，Atomic 不得反调、专家不因覆盖某模态就过度触发。
  • 专家审查 ≤2 轮：交付前必检（海报用原生视觉、视频用 understand_video）→ 问题归到最小责任层 → 增量重做、复用已验证资产 → 默认最多两轮，两轮后把决定权交回用户。
  • 禁原地更新、必换 asset_id：重生成 image 必得新 id，重组装前必须把 code 任务的 depends_on 与 get_asset() 解析路径改指新 id，否则会静默复用旧的失败资产（仓库显式警告）。
  • 五类中断、增量改 DAG：单任务局部改 / 全局风格改 / 加任务（增量插入现有 DAG、id 顺延）/ 取消任务（下游标 cancelled、不写注册表）/ 换话题（先确认、清空本轮 DAG、已完成资产保留）——本质是动态重规划而非整体丢弃。
  • plug-and-play 的工程形态：宿主只需 symlink 技能目录 + 注册一个 stdio MCP（skill.yaml），不动宿主 prompt 与预算——这就是「不改推理核心」的落地动作。

① InterventionPolicy 三态状态机（示意性实现）

综合 ALIVE 的三态动作词汇、Coco 的隐式反馈降频、Pitch 的「每日每种至多一次 / 可拒绝」约束与 Pandora 的克制检查，得到干预策略器的决策骨架。所有分支都显式返回三态之一——沉默也是返回值，不是缺省。

// [示意性实现] 综合 ALIVE / Coco / Pandora / Omni-IO 四篇设计，非论文原码
enum State { RESPOND, SILENT_MONITOR, SEEK_FEEDBACK }

struct Decision { state: State, topic?, budget: 1, channel, reason }

fn decide(obs, profile, intention, feedback, quiet) -> Decision {
    // ① 静默时段：沉默是显式动作，不是缺席（ALIVE 三态）
    if quiet.in_window() { return silent("quiet-hours") }

    // ② 隐式反馈降频：被忽略 N 次 → 该触发降频并记负反馈（Coco 环）
    if feedback.dismiss_count(obs.trigger) >= profile.N {
        profile.deprioritize(obs.trigger)
        return silent("cooldown")
    }

    // ③ 每日预算：每类触发每日至多 1 次（Pitch 反面清单 → 正向约束）
    if budget.exhausted_today(obs.trigger) {
        return silent("daily-cap")
    }

    // ④ 时机打分：干预时机是可度量目标（Coco：macro F1 的输入）
    score = model.p_helpful(obs, profile.interaction_profile)

    if score < profile.threshold_ignore  { return silent("not-useful") }
    if score < profile.threshold_act      { return seek_feedback("clarify") } // 一次一问

    // ⑤ 出声：内容决策 → 表达规划(StyleLexicon) → 克制检查(Pandora 分层)
    content = task.plan(obs)
    wording = style.realize(content, profile.style_lexicon)
    if guard.overpromise(wording) || guard.mind_read(wording) {
        wording = guard.soften(wording)   // self-opaque：不猜心、不承诺效果
    }
    return respond(wording, budget = 1)  // 可跳过 / 可拒绝
}

② Coco 式 Observer：信号 → 特征 → 决策骨架（示意性实现）

独立 Observer subagent 的最小骨架：本地观察（原始活动不出设备）、选择性保留紧凑上下文、把四类隐式信号聚合成时机标签。标签按周聚合后即可算 macro F1——「先有标签，后有学习」。

// [示意性实现] 依 papers-abstracts.md §1 摘要结构重写，非论文原码
class ObserverAgent {
    // 隐私边界：只在本机处理，原始活动流不外发（on-device）
    def on_event(raw_activity):        // raw 永不出设备
        local = self.device.extract_features(raw_activity)
        ctx   = self.selective_retain(local)   // 紧凑长期用户建模上下文
        self.memory.update(ctx)

    def signals(event):                // 四类隐式信号
        return {
            "engagement":        event.clicked || event.kept_open(),
            "dismissal":         event.closed() || event.swiped_away(),
            "explicit_request":  event.user_asked(),
            "repeated_pattern":  self.is_repeated_work(event.window),
        }

    def label_for(trigger):            // 时机标签 = (触发, 是否被打断/采纳)
        s = self.signals(trigger.last_event)
        if s["dismissal"] and not s["engagement"]: return 0
        if s["explicit_request"] or s["engagement"]: return 1
        return -1                          // 灰区：不计入当轮，按周聚合

    def weekly_eval(labels):            // OSWorld-Persona 式：先有标签才可学
        y, yhat = align(labels), self.policy.predict(labels)
        return macro_f1(y, yhat)        // 论文自报 0.199→0.515 的口径参考
}

def _save(self, store: dict[str, dict]) -> None:
    """Write atomically via a temporary file and rename to preserve history on crashes."""
    tmp_path = self._path.with_suffix(".json.tmp")
    tmp_path.write_text(
        json.dumps(store, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
    os.replace(tmp_path, self._path)      # 全平台原子替换

延伸问题

延伸问题 Q1

干预时机的隐式反馈是否存在「冷启动—打扰」权衡的理论下界？

理论分析：Coco 的闭环以「有标签才可学」为前提，但标签恰恰产生于干预之后——不干预就没有 engagement/dismissal，干预就可能造成打扰。这可以形式化为标签稀缺下的探索—利用问题：设单位打扰成本为 c、一次正确干预的收益为 r，冷启动期任何主动干预的期望净收益为 p·r − (1−p)·c，其中 p 是先验合意概率。当 p < c/(r+c) 时主动干预在期望上必然为负——这给出一个不依赖具体模型的下界：先验合意概率低于阈值时，任何策略的冷启动期都不可能「既学到标签又不付出打扰」。阈值本身随用户而异，因此冷启动成本无法被彻底消除，只能被分摊（例如借用群体先验抬高 p 的初值，或把探索约束在低打扰渠道上）。

研究方向：① 把该下界写成关于 (c, r, p₀) 的显式命题，并在 OSWorld-Persona 式基准上验证其紧性；② 设计「低打扰探针」——用零打扰信号（重复工作模式、时段统计）先验地抬高 p₀，缩短纯探索期；③ 研究降频策略（被忽略 N 次降频）在该框架下的 regret 行为，比较它与 Thompson 采样类方法的样本效率。

延伸问题 Q2

表达风格蒸馏的保真度与隐私边界如何权衡？

理论分析：Pandora 的 StyleLexicon 与 Coco 的紧凑用户建模上下文其实是同一类对象：用户语言/行为画像。画像越精细，表达越「像本人」（Pandora 自报 AI 味 7.2%自报·未复现正来自这种精细度），但它也越容易被反推身份——风格模型本质上是一个可查询的说话人指纹：给定足够多的生成样本，攻击者可以做说话人归因、甚至重建训练语料片段。于是存在一条清晰的权衡曲线：保真度 ↑ ⇒ 身份泄露面 ↑。更微妙的是 self-opaque 纪律带来的双重约束：既不能说得比本人更清楚（内容侧），也不能说得太像本人（风格侧的极端）——「像」与「不像」之间的可接受带宽本身就是隐私预算的函数。

研究方向：① 定义风格蒸馏的隐私度量（如从生成样本反推原说话人的成功率），与表达相似度一起画成 Pareto 前沿；② 研究分层保留策略——固定画像层不被召回污染、StyleLexicon 只存句式骨架不存内容实体（与第 4 篇「固定画像层」共识对齐）；③ 探索差分隐私式风格抽取（对高频句式计数加噪）在小语料下的可用性下界。

延伸问题 Q3

主动性系统的「False-Alarm–Recall 权衡」是否存在与异常检测同构的理论边界？（全文精读新发现）

理论分析：Coco 全文 Table 1 给出了摘要级阅读看不到的代价曲线：适配后 macro F1 从 0.1861 升到 0.4832，但 False-Alarm 同步从 0.0468 涨到 0.2492——作者坦承这是「从近乎沉默转向主动干预」的必然代价。这与经典异常检测/医学筛查的 ROC 结构同构：主动干预本质上是一个二元分类器架在稀缺正例上（Table 4 显示正例占比随 persona 从 81% 到 3.5% 剧烈变化），任何提升 recall 的策略都会推高 FA。理论问题是：在正例先验 π 因人而异（Eager Hands-on 81% vs Learning-oriented 3.5%）且标签由同一策略产生（标签-策略耦合）的条件下，Bayes 最优阈值是否仍落在固定 F1 最大点，还是必须把打扰成本显式入损失（FA 的单位代价 ≫ FN 的单位代价时，F1 最优点系统性偏保守）才能得到可部署的策略。Coco 的 |score|<0.45 留白 与 OIA 的「每日至多一次」其实都是在没有代价权重时的手工正则替代品。

研究方向：① 把干预时机形式化为代价敏感学习问题，推导 Bayes 阈值随 (π, cFA, cFN) 的移动方向，并用 Table 1 三 persona 的 (P, R, FA) 三点做经验校验；② 设计「per-persona 代价自适应」：由 InteractionProfile 估计该用户的打扰弹性，动态调整阈值而非用全局 0.45；③ 评测协议上主张报告 PR 曲线而非单点 F1——因为正例先验跨 persona 差 23 倍，单点 F1 不可比；④ 复现检查：以论文引言「up to 0.77 F1」与 Table 1 最高 0.8609 的口径疑点为切入点，建立「自报数字 vs 表格单元格」的一致性核对清单（本页 Coco、Omni-IO 两章已发现两处此类不一致）。
