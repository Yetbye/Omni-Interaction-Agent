CHAPTER 00

这是什么 · 怎么读

这是 Omni-Interaction-Agent（OIA）立项调研的配套读书博客：把「值得借鉴的项目与论文」从 README 级的了解，推进到源码级、公式级、机制级的理解。所有材料来自本机实读的 7 个开源仓库、13 份文档快照与 5 篇论文摘要原文，全站离线可读。

三条主线贯穿七页：记忆 Memory委托·主动性·一致性个性化 Personalization，外加一条收束线 全模态 IO 与基座。每页独立成篇，带自绘图解、源码摘录与「延伸问题」；读完最后一页，你会看到它们如何拼成一套完整设计。

深度洞察

这不只是「项目简介合集」，而是一次逆向工程式的学习

每个项目都被追问同一组问题：为什么这样设计？代价是什么？换一种方案会怎样？代码里的常量与公式究竟在干什么？——例如 rolling-memory 把「汉字 10 bit、字母 2 bit」写进权重函数，琥珀之心把 48 小时写成可配置的审核等待期，Hy-Memory 明确「diff-chain 是装饰器不是检索器」。这些细节才是可迁移的知识。

方法论：先读源码与原文，再下结论；所有项目自报数字均标注「自报·未复现」。

CHAPTER 04

自主科研问题（五问）

不是复述项目 README 的「未来工作」，而是从源码与公式里读出来的、尚未被这些项目回答的问题。每问附理论分析与研究方向；各页页尾另有页内延伸问题。

延伸问题 Q1

语义金字塔各层的 token 预算，能否按查询类型联合优化？

理论分析：把注入窗口视为约束优化——目标是最大化证据效用（GraphMemix 的 evidence utility 视角），约束是各层（画像/场景/事实/原话）预算之和 ≤ B。查询类型 t 决定各层的边际价值曲线 ∂U/∂bᵢ(t)；分层记忆的意义恰在于让边际价值随 t 重排，而非静态分配。腾讯云的渐进披露（顶层 Markdown、底层 DB）本质是这个优化的贪心解，但未给出按 t 的分配律。

研究方向：在 OIA 上做查询类型分类器 + 分层预算的在线分配（多臂赌博机形式），对照静态分配测 token 省量与召回率。

延伸问题 Q2

词法-向量混合检索的权重 w_vec，是否存在依赖查询「标识符密度」的最优值？

理论分析：rolling-memory 自报 w_vec=0.15 融合提升 Recall@10，而等权 w=1.0 反伤 Hard 集（自报·未复现）——说明两路分数分布不可比，且最优混合随查询中精确符号（函数名/错误码/日期）的占比漂移：标识符密度高时词法近乎充分，向量是噪声源；自然语言省略指称时相反。形式化为按查询熵 H(q) 条件化的 w*(H)。

研究方向：用查询的自信息特征（恰是 rolling 的 RuneShannonBits）预测最优混合权重，构建自适应 T0/T1 路由。

延伸问题 Q3

证据森林的「证据预算」与 harness compaction 的「token 预算」能否统一为同一目标函数？

理论分析：两者竞争同一注入窗口：GraphMemix 在证据预算下最大化关系结构效用，compaction 在窗口压力下最小化信息损失（DSH 的 surface 替换 + shadowedTokenCount 记账）。若把「压缩后仍可下钻回原文」视为硬约束（本系列的证据链原则），则两者是同一拉格朗日问题的读侧与写侧——λ 是窗口影子价格。

研究方向：在 OIA 的 compaction 后端与 recall 预算器之间共享同一个 λ，做读写联动的窗口调度实验。

延伸问题 Q4

主动干预的隐式反馈学习，是否存在「冷启动-打扰」权衡的理论下界？

理论分析：Coco 用 engagement/dismissal 等隐式信号把 macro F1 从 0.12–0.19 提到 0.35–0.48（自报·未复现），但每个负反馈（dismiss）同时是一次真实打扰成本——标签本身由干预产生，构成「探索-利用-打扰」三方权衡：在标签稀缺的冷启动期，任何主动都是在用用户体验购买学习信号。下界直觉：打扰预算 D 限制了每轮可采的负样本数，从而限制 F1 收敛速度。

研究方向：形式化打扰预算约束下的最优探索策略；用 pitch 门户的三缺陷（僵化/抢话/过度承诺）作为打扰成本的可测代理。

延伸问题 Q5

「不 fork 内核」的二次开发，其深度定制上限在哪里？

理论分析：DSH 的能力 seam 允许替换一切被文档化的扩展点（llm/tools/subagents/goal/schedule/compaction…），但循环语义本身由 agent-loop 拥有（turn/step 生命周期、提示词准入）。定制需求可分成三类：seam 内（零 patch）、需新 seam（中等）、触碰循环语义（必须最小 patch 分支）。其可维护成本 ≈ patch 行数 × 上游变更频率——存在一个随上游演进移动的「定制天花板」。

研究方向：做一次 seam 覆盖度审计：把 OIA 需求清单逐条映射到三类，量化天花板位置，并在升级演练中测量 rebase 成本。
