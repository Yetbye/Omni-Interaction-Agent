0 · 执行摘要

一句话定位：Omni-Interaction-Agent 是一条与日常工作环境完全隔离的智能体 harness 二次开发线—— 以 DeepSeek Harness（DSH）的 Cordis 插件架构为骨架，吸收 Pi Agent 的极简扩展哲学， 把「记忆 / 委托与主动性 / 一致性 / 个性化 / 全模态 IO」做成一套可组合的插件族（@omni/*）， 面向实时交互式全模态智能（Native Real-Time Interactive Omni Intelligence）。

三个最重要的结论：

  1. 基座选 DSH，不另起炉灶。DSH 的能力 seam 体系（ctx.llm / tools / subagents / goals / schedule / skills / storage / workflow） 天生就是委托、主动性、一致性的落点；文档明示「无特权内核，一切皆插件、皆可 patch 替换」， 意味着我们能在不 fork 内核的前提下做出完整产品。Pi 的价值在两处：极简扩展模型（extensions / skills / packages） 与 pi-ai 统一 LLM API——而 DSH 已内置 dsh-llm-pi-ai 适配包，两者天然可组合。
  2. 记忆是 OIA 的第一支柱，且必须「白盒、可追溯、可被人类治理」。综合 腾讯云 TencentDB-Agent-Memory 的分层金字塔 + 符号画布、rolling-memory 的「原文档案 + 零成本词法检索」基线、 Hy-Memory 的双过程认知与 diff-chain、MemoraX 的四类记忆边界、GraphMemix 的查询感知证据森林， 以及三个社区插件（续忆 / 琥珀之心 / Anima Brain）的「人审、纠正、抑制、召回透明」机制， 我们提出 OIA-Memory 五组件（Vault / Distiller / Canvas / Recall / Governance），见 §4.6。
  3. 隔离是硬约束。独立 DSH_HOME、独立 profile、独立插件命名空间、独立记忆库、独立工作区目录； 与当前在用的 DSH Desktop（profiles/desktop）和五个项目门户零共享、零侵入，检查清单见 §1。
⚠️ 阅读须知（诚实边界） 本报告中所有基准数字（如 PersonaMem 48→76、ATM-Bench Recall@10 82.85%、token −61% 等）均为各项目自报，未独立复现，引用时一律标注来源； 《Native Real-Time Interactive Omni Intelligence》综述仅有用户本地 PDF，公开渠道检索不到，本报告只将其作为方向性指导，不引用其任何具体论断（见 §10）。

1 · 边界与隔离设计（含门户冲突检查）

1.1 为什么强调隔离

用户要求明确：OIA 用的 DeepSeek Harness 必须是隔离的、专门适配 Omni-Interaction-Agent 的新实例， 而不是当前会话正在使用的 DSH。当前在用的 Desktop 发行版（dsh-desktop-next 2.0.23-next， Profile：desktop，Home：~\.dsh）承载日常研发，绝不能被本项目的实验性组合包、 HMR 重载、插件安装事务所影响。隔离同时也是产品要求：Omni-Interaction-Agent 将来作为独立产品分发， 必须自带运行时边界。

1.2 五层隔离红线

层隔离手段具体约定
代码独立目录 + 独立 git 线 工作区新门户 omni-interaction-agent/；二次开发以 deepseek-harness 开源仓库为 upstream， 自研内容全部放在 @omni/* 组合包与 patch 层，尽量不改内核；必须改内核时走「最小 patch 分支 + 可 rebase」策略。
运行时独立 DSH_HOME 与 profile DSH_HOME=%USERPROFILE%\.omni-dsh；profile 命名 omni（组合包 @omni/omni-base）； 端口与 IPC 名独立（如 web 端口 8848 起），与当前 Desktop 的系统分配端口不冲突。
插件命名空间与安装事务隔离 插件 id 一律 @omni/…，不复用 @deepseek-ai/… 官方 id； 禁止向当前 ~\.dsh\profiles\desktop 安装/启用任何 OIA 插件。
数据独立记忆库与会话日志 记忆库 ~\.omni-dsh\memory\（SQLite + 附件区）；会话 JSONL 也落在 OIA 自己的 home， 与 ~\.dsh 无任何读写交集。
工作区独立门户目录 仅 omni-interaction-agent/ 一个入口；不 import、不复制、不改动其余五个项目门户的任何文件。

2.2 结论：DSH 为主基座，Pi 为生态补给

选型决策（已定，不再询问）
  • 主基座 = DeepSeek Harness：OIA 的核心命题（Delegation / Proactivity / Consistency）恰好一一命中 DSH 的 subagent+teams / schedule+goals / session-log+projections 三大 seam 群。二开形态为叠加组合包（bundle）+ patch 层，不 fork 内核——这正是 DSH 文档推荐的扩展方式（「新行为附加到已有文档记录的扩展点」映射表）。
  • Pi 生态为补给：① pi-ai 已通过 dsh-llm-pi-ai 进入 DSH，Omni 多模态模型接入优先扩这条适配线；② Pi 的 extensions/skills/prompt-templates/packages 模型作为 @omni/* 包设计的对照参考；③ Pi 的 RPC/SDK/JSON 模式启发 OIA 的 headless 集成面。
  • 不选 Pi 为主基座的理由：委托与主动性都要从零造，且无权限系统；对「实时交互全模态智能体」而言，事件溯源会话日志（一致性底座）是刚需，DSH 现成。

4 · 主题一 · Harness Memory 深度拆解

以下逐项给出：它是什么 → 机制要点 → 值得借鉴 → 不借鉴/风险 → 在 OIA 的落点。 所有数字均为项目自报。资料原文存档于 omni-interaction-agent/docs/sources/。

4.1 TencentDB-Agent-Memory（腾讯云）工作场景首选

它是什么：团队级记忆中枢：把对话/文档/代码沉淀为四类可复用记忆资产（Chat Memory / Skill / LLM-Wiki / Code-Graph）， 带治理与共享面板，官方提供 OpenClaw 插件、Hermes 网关，甚至有 DSH 适配文档（Anthropic Messages 协议接入细节，见 sources/tencent-dsh-adapter.md）。

机制要点：

  • 长短期两套分层：长期 L0 对话→L1 原子事实→L2 场景→L3 人格（语义金字塔）；短期 refs 原文卸载→jsonl 步骤摘要→Mermaid 符号画布（node_id 可下钻回原文）。
  • 异构存储 + 渐进披露：底层（事实/日志/轨迹）进数据库供全文检索，顶层（人格/场景/画布）存人可读 Markdown；「下层保存证据，上层保存结构」。
  • 全链路可追溯：人格→场景→原子→原对话的确定性下钻，拒绝不可逆有损压缩。
  • 记忆即负载（loadout）：私有/团队/受限/agent 四级可见性 + ACL，按 Agent 绑定不同资产；Skill 是带版本、资源、触发边界、校验规则的一等资产。
  • 知识按需：Wiki 与 CodeGraph 是工具化查询而非整体注入，「不让 Agent 每次先读完整文件清单再干活」。
  • 自报数据（OpenClaw 集成）：WideSearch token −61.38%、通过率 +51.52%（相对）；PersonaMem 48%→76%。

值得借鉴：① 语义金字塔 L0–L3 作为长期记忆主干；② Mermaid 符号画布 + node_id 下钻（上下文卸载与可追溯兼得）；③ 白盒调试（记忆目录即文档）；④ 资产 ACL 与 per-agent loadout；⑤ 「压缩不牺牲证据链」是硬约束。
不借鉴/风险：依赖 LLM 后台持续抽取（token 成本、延迟）；其 Benchmark 为自报；云向量库后端不需要。
OIA 落点：@omni/memory-distiller（L1–L3 蒸馏）+ @omni/memory-canvas（符号画布 compaction 后端）+ 治理面板的 ACL 设计。

4.2 rolling-memory（Agent Memory 挑战赛佳绩 · 开源）零成本基线

它是什么：本地优先、source-available 的编码智能体长期记忆：单个 Go 二进制 + 本地 SQLite 库， 向连接的 agent 暴露唯一一个 MCP 工具 recall；零云端、零向量、零后台 LLM 调用，约 30ms 检索。PolyForm 非商用许可（商用需注意）。

机制要点：

  • 原文档案铁律：「历史发生即记录」，绝不在入库时用 LLM 改写/摘要——「用可能幻觉的模型去改写可能被误解的对话是错误复合」；只做确定性格式清理（去协议外壳、thinking 块、重复日志行）。
  • 无向量信息论检索核：纯子串分词 + 聚类排序，三机制——自适应自信息与突发克隆折叠（同日重复日志对数折叠，不稀释稀有词）、确定性跨形态对齐（「May 12, 2025」↔「2025-05-12」、复合标识符、500ms/16GiB 数量单位对）、多线索共振（查询多个稀有线索短窗口共现加权）。
  • turn-elimination 经济学：长上下文（100k–400k token）下每次免掉的盲搜轮 = 省一次全上下文重发；有专门的 falsification 文档与 24h/7 天自用审计（自报：81.8% 命中卡省了平均 4.3 盲搜轮；89.1% 召回结果被后续采纳）。
  • 评测文化：ATM-Bench Recall@10 82.85%（Main）、LoCoMo 端到端 85.26%（自报）；词法骨干 + 小权重向量融合（w=0.15）再涨，等权融合反而伤 Hard 集。
  • 单文件 USB 便携模式；对 grep 的边界论证（background-vs-grep 文档）。

值得借鉴：① 先建零成本 verbatim + 词法检索基线，再谈向量/图谱（与 TensorDB 的 BM25+向量 RRF 相互印证）；② 采纳率审计（记忆是否真被用上）作为一等指标；③ 「摘要会丢证据」的反面教材转为我们的「摘要必须挂原文链」约束；④ 数字字面量/标识符的跨形态对齐对编码场景极其有效。
不借鉴/风险：纯词法对自然语言零重叠查询（昵称/省略主语）弱——这恰是社区陪伴场景的主战场，需向量+图谱补；非商用许可，思路可用、代码不并入。
OIA 落点：@omni/memory-recall 的检索分级（T0 词法 → T1 向量 → T2 图谱）与采纳审计事件。

4.3 memorax-code（国内记忆公司 MemoraX 开源部分）工程化最完整

它是什么：面向 Codex / Claude Code / DeepSeek Harness / Cursor 等 9 种客户端的共享记忆层 npm 包： 跨会话召回、可复用经验沉淀、仓库知识、个人偏好延续；云端记忆为产品主体（90 天访客模式），开源部分含客户端集成与本地 Backend。

机制要点：

  • 四类记忆边界（问题域划分，非常清晰）：Coding Memory（工程经验教训）/ Repo Memory（仓库架构图、模块归属、入口、commit/PR 证据）/ Personal Memory·User Profile（语言、语气、解释深度、结果格式）/ Procedure Memory（可复用步骤、检查单、校验门）。
  • 意图式保存 + 语义去重：用户说出「想长期生效」的规则即存（不等说“记住”）；写入前语义比较——等价则不动、精炼则更新并保留被取代措辞、过时才删除；一次性任务指令不入记忆；意图不明先问再写。
  • 节奏化注入防遗忘：User Profile 首个合格轮注入 + Procedure 按提醒节奏（默认第 1/6/11 轮、此后每 5 轮）；compaction 后下一轮恢复注入。
  • 记忆影响可见：最终答案开头用一句自然语言注明「本次哪些记忆实际影响了任务」（透明度设计）。
  • Repo Memory 后台维护：默认分支基线一份、各 worktree 复用并校验，由原生后台 subagent 构建/更新。
  • 本地可观测：trace + reconciliation 记录，可查检索/写回状态与失败。

值得借鉴：四类边界直接采用为 OIA 记忆分类；「保存按意图 + 语义去重 + 取代留痕」的写入策略；记忆影响披露；节奏化注入（防 compaction/长任务遗忘）；Repo Memory 基线复用思想。
不借鉴/风险：云端账户依赖与自动写回无二次确认（隐私默认偏激进）；与我们「本地优先」相悖，仅取机制不取服务。
OIA 落点：@omni/memory-distiller 的写入策略；@omni/persona 的注入节奏；答复级「记忆影响披露」进 OIA 文案规范。

4.4 Hy-Memory（腾讯混元）+ MemHub 认知架构参照

它是什么：生产级双过程认知记忆引擎（Python SDK hy-memory）+ 本地优先桌面汇聚产品 MemHub。 配套三篇论文（EMNLP 2026 双过程记忆、CMB 编码记忆基准、Hy-Memory-30B-A3B 归因强化学习记忆写入模型）。

机制要点：

  • 双过程：System 1（lite/pro：快速读写检索）+ System 2（ultra：evolve() 触发 schema 归纳、跨域清扫，需图库）。
  • Chat 场景 8 层：L0 基本信息 → L1 原始对话 → L2 原子事实（版本化不可变）→ L3 摘要 → L6 SCHEMA 心智模型（叙事模板、图层）→ L7 INTENTION 前瞻意图（带过期，过期降级为普通事实）。
  • Working/Coding 双层：Facts（本会话做了什么，1 条/会话）+ Experiences（可复用解法，0–N 条需过价值阈值），双向互链；被取代事实走任务进展链可追溯。
  • Coding 版本演化 diff-chain：事实抽取刻意不贴代码（预算留给坐标），而被 revert 的版本连工作树里都没有——diff-chain 用零 LLM 成本存每版真实 diff，是「装饰器而非检索器」，挂在事实下面。
  • 场景路由（chat/working/coding）与来源隔离（source 过滤）；lite/pro/ultra 三档模式。
  • MemHub：把 Claude Code / Cursor / Codex / OpenCode / Qwen Code 等的对话与轨迹统一汇聚到本地受治理记忆（对多入口 Omni 交互是关键形态）。

值得借鉴：① 双过程（快检索 + 慢整理）作为 OIA-Memory 的运行节律；② L7 前瞻意图层（「下周一要交报告」）对主动性极有价值；③ Facts↔Experiences 双层互链；④ diff-chain 挽回「说错又撤回」的版本——与会话事件日志天然同构；⑤ MemHub 式跨 harness 汇聚对应 OIA 未来多入口（QQ/桌面/语音）。
不借鉴/风险：8 层全量对个人场景过重（默认参考 L0–L3+L7）；30B 记忆写入模型不引入（用现有 LLM 蒸馏）。
OIA 落点：Distiller 的分层目标模型；diff-chain 挂载到 @omni/memory-vault 的编辑历史；意图层进 Observer 的触发源。

4.5 GraphMemix（论文 · memorax 技术博客对应）检索组织学

要点：把长期记忆组织建模为查询感知的证据森林构造（组合优化）： ① 候选图构造（多视角种子记忆经 schema+语义关系扩展）； ② 证据效用与激活成本解耦（直接记忆支持 vs 锚点条件关系验证，抑制冗余/冲突）； ③ 森林优化（最大证据预算下选森林结构）。避免了「问题无关的离线摘要」与「朴素向量相似」两坑， 能找回低相似但互补的证据，在四个长期多模态记忆基准上改善准确率-生命周期成本的 Pareto 前沿。
值得借鉴：召回不应是「相似度 Top-K 灌入」，而是带预算的证据选择问题——查询感知、效用-成本核算、去冗余去冲突； 低相似互补证据的恢复对「用模糊描述找旧事」至关重要。
OIA 落点：@omni/memory-recall 的候选合并与预算化精排（与琥珀之心的两级精排合并设计）。

5.2 论文洞见 → harness 转译

ALIVE（2611.21366）——用户判断「直接来看没什么参考价值」（其训练法确不可迁移），但注意它恰好定义了交互式流模型的三态决策：何时响应 / 如何响应 / 何时沉默，外加反馈寻求（feedback-seeking）；对比式 SFT 教「何时与如何」，RL 的 BACA 用轨迹级+局部信用分配调「决策、响应与沉默」。 转译到 harness：主动性不是「多说话」，而是把「出声 / 沉默监测 / 主动追问」建模为可评估的动作序列——这直接决定 OIA 干预策略器的输出词汇表（§5.3），且「沉默」必须是显式动作而非缺席。

Deep Personalization / Coco（2611.13457）——桌面主动智能体：独立 Observer Agent 持续观察桌面活动、维护紧凑长期用户建模上下文、并从隐式信号（投入、忽略、显式请求、重复劳动模式）学习「何时帮助合意」； 本地运行不外发原始活动流；OSWorld-Persona 基准把干预时机变成可测标签（macro F1 0.12–0.19 → 0.35–0.48，自报 2.4–3.0×；一周用户研究 0.199→0.515）。 转译：观察者独立成 subagent（不占主对话上下文）；干预时机个性化是可度量目标；隐式反馈（被关掉=负反馈）进策略学习环。

Pitch（本工作区 pitch 门户，CHI 2026）的三大缺陷——僵化、抢话、过度承诺，是主动性设计的现成反面清单： OIA 文案与策略必须允许随时跳过/换题/拒绝，一次只问一件事，未回复不追问，措辞克制不承诺效果。

5.3 OIA 干预策略器（设计定稿）

InterventionPolicy.state : {RESPOND, SILENT_MONITOR, SEEK_FEEDBACK}

输入  : 观察事件流(Observer subagent) × 用户画像(L3) × 意图层(L7, 带过期)
       × 隐式反馈(engagement / dismissal / 显式求助 / 重复模式) × 静默时段
输出  : {state, topic?, budget: 1 问/次, channel: 会话内|轻唤|不打扰}
约束  : 每类触发每日至多 1 次(借 Pitch「每日每种至多一次」)；
       被忽略/关闭 N 次 → 该触发降频并记录负反馈(Coco 环)；
       RESPOND 必须可被跳过/拒绝，措辞模板内置克制条款(不过度承诺)。
学习  : 时机标签 = (触发, 是否被打断/采纳)，按周聚合，进 OSWorld-Persona 式评测集
